THREE TECHNICAL BOTTLENECKS

CHALLENGE 01

極短序列與資料稀疏性

消費者平均互動次數極少且存在新上架冷啟動商品。傳統 Transformer 全域自注意力透過 Softmax 強制歸一化（∑α=1），在短序列中極易將權重過度稀釋給隨機雜訊點擊。

Over-attribution of random clicks
CHALLENGE 02

不規則時間與 O(N²) 算力消耗

真實購物間隔不規則（「兩天前」與「半年前」意圖權重截然不同）。現有時間感知 TiSASRec 需建構 T×T×d 高維時間差張量，造成 O(N²) 顯存與算力爆炸，在 4–8GB 邊緣卡極易 OOM。

TiSASRec Tensor: O(T² · d) VRAM
CHALLENGE 03

地端 LLM 部署與協同知識缺失

企業因隱私與 API 成本傾向地端部署開源 LLM，但若直接輸入百級候選清單會導致 KV Cache 溢位與高延遲；且通用 LLM 缺乏電商共購協同知識，易產生推薦幻覺。

PHYSICAL DECAY KERNEL

Softplus 正向約束杜絕逆時序反常

Gt = ht ⊙ exp( -Softplus(λ) · (Δti / 30.0) )

Softplus(x) = ln(1 + eˣ) > 0 強制衰減速率嚴格非負，防止梯度更新出現「間隔越久權重越大」的異常，並消除炎夏短袖舊特徵對寒冬大衣推薦的干擾。

論文真實樣本驗算（顧客 409d84ac...）：
Δt = 19.0 天、ht,k = 0.820、λk = 0.5
Softplus(0.5) ≈ 0.974 → exp(-0.974 × 19/30) ≈ 0.539
最終意圖值：Gt,k = 0.820 × 0.539 ≈ 0.442

MULTI-TASK OBJECTIVE

三任務聯合梯度訓練：同步收斂單品精度、品類泛化與回購週期

Ltotal = Litem + α · Ltype + β · Ltime    (設定 α = 0.5, β = 0.1)
TASK 1 // 商品預測

Litem = -(1/B) ∑ ln P(vi|Si)

預測下一時刻目標單品。實測 P = 0.35 → Litem = 1.050。

TASK 2 // 品類輔助

Ltype = -(1/B) ∑ ln P(ci|Si)

以群體品類語意補強冷啟動。實測 P = 0.78 → Ltype = 0.248。

TASK 3 // 時間回歸

Ltime = SmoothL1(Δt̂i, Δti)

誤差 >1 天採線性懲罰。預測 13.8 vs 15.0 天 → Ltime = 0.700。

= 1.244

ALGORITHM SPECIFICATION

系統端到端推論演算法（Steps 01–17）

PHASE 1 // CT-MambaRec (Steps 1–7)
  1. 計算物理天數差 Δti = ti - ti-1
  2. 查表提取四路嵌入向量 ebase
  3. 注入圖投影 xin = ebase + Wgraph(ebase)
  4. 選擇性狀態空間掃描輸出 ht
  5. 應用 Softplus 指數物理衰減 Gt
  6. 計算全域 Logits Smamba 與 Δt̂N+1
  7. 截取 Top-100 候選集 Cretrieval
PHASE 2 // XGBoost CPU (Steps 8–11)
  1. 於 CPU 為 Top-100 建構特徵向量 xi
  2. 計算價格溢價差異率 Pdiff
  3. 100 棵決策樹評估 Scorexgb(i)
  4. 壓縮 90% 截取 Top-10 集 Ccoarse
Stage 1 產出後即刻釋放 GPU 快取，Stage 2 全程於 CPU 主記憶體運算。

  1. 組裝協同先驗提示詞（≤280 Tokens）
  2. 4-bit 量化 LLM 執行單次前向傳播
  3. 提取標籤 Y={A..J} 之 Next-Token Logits
  4. Softmax 計算各選項推薦勝率
  5. Argmax 選定唯一商品 v
